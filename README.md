## ◈ لمحة عن المشروع

**NexusServiceCloud** حزمة تحليل وتصميم لمنصة موحدة لإدارة الخدمات والدعم الفني. تهدف الرؤية إلى توحيد استقبال الحوادث وطلبات الخدمة، وإدارتها وفق اتفاقيات مستوى الخدمة، وربطها بالمشكلات والتغييرات والإصدارات والمعرفة والأصول والمشتريات والعقود.

> **حالة المستودع:** هذه حزمة مواصفات مستهدفة وليست تطبيقًا منفذًا. لا تحتوي على شيفرة تطبيق جاهزة للتشغيل، أو إعدادات تشغيل، أو ترحيلات قاعدة بيانات، أو اختبارات تنفيذية. أي ادعاء بالتنفيذ أو الجاهزية للإنتاج خارج نطاق هذه الحزمة.

| المجال | القيمة المستهدفة |
|---|---|
| إدارة الخدمات | حوادث، طلبات خدمة، كتالوج، تصنيف، تعيين، تعليقات، ومرفقات |
| مستوى الخدمة | SLA/OLA، تقاويم عمل، مقاطع قياس، تصعيد، ومؤشرات زمن الخدمة |
| التحكم التشغيلي | مشكلات، تغييرات، موافقات، مشاكل معروفة، وإصدارات |
| المعرفة والتسليم | قاعدة معرفة، مشاريع، مهام، تبعيات، ونشر مسجل |
| الموارد | ربط بالأصول، CMDB، المشتريات، العقود، الصيانة، والحجوزات |
| تعدد المستأجرين | عزل مؤسسات مستقلة مع أقسام/مكاتب خدمة داخل المؤسسة |
| الحوكمة والتدقيق | صلاحيات، تدقيق، قرارات معمارية، وتتبع متطلبات |
| قنوات الوصول | واجهة ويب، BFF، API، واستراتيجية هاتف مقترحة |

## ◈ المعمارية المستهدفة

| الطبقة / القناة | الهدف |
|---|---|
| المستخدمون | مستفيدون، فنيو دعم، قادة فرق، مالكو خدمات، مديرو تغيير/مشكلة/أصول، مدققون |
| الدخول الآمن | بوابة اتصال آمن، TLS، توجيه، وضوابط حافة |
| الواجهة | ويب إداري/تشغيلي مع طبقة BFF لتجميع قراءات الشاشة وحماية الجلسة |
| التطبيق | حالات استخدام، تنسيق سير العمل، قواعد تفويض، وأحداث مجال |
| المجال | وحدات أعمال مستقلة منطقيًا ضمن نمط Modular Monolith |
| البيانات | تخزين علائقي للحقيقة التشغيلية، عزل مستأجر، ومرفقات في مخزن مستقل |
| العمليات الخلفية | إشعارات، مواعيد SLA، أحداث موثوقة، ومعالجة غير متزامنة |
| التكاملات | بريد، مراقبة، اكتشاف/أصول، هوية، ومزودات خارجية عبر عقود صريحة |

### اتجاه الاعتماد

| القاعدة | المعنى |
|---|---|
| اتجاه الاعتماد | `Interfaces -> Application -> Domain` (إلى الداخل فقط) |
| البنية التحتية | تنفذ المنافذ/المحولات ولا تملك قواعد العمل |
| نقاء المجال | المجال لا يعتمد على HTTP أو ORM أو مزودات خارجية |
| التفويض | قرار الصلاحية النهائي في الخادم لكل عملية وكل كائن |
| الاتساق | تحديث الحالة والتاريخ والتدقيق والأحداث الموثوقة ضمن حدود معاملة واضحة |
| العزل | فصل مؤسسات مستقل؛ القسم داخل المؤسسة ليس مستأجرًا تلقائيًا |

## ◈ العلاقة بالمراجع

وثائق NexusServiceCloud الأصلية هي مصدر نطاق العمل. استُخدم NexusAsset CloudMonorepo مرجعًا لتنظيم الوثائق وفصل المجال والتطبيق والبنية التحتية والحوكمة. لا يعني ذلك نسخ مجال اكتشاف الأصول، أو اعتماد Lansweeper، أو نقل إصدارات الحزم وخطط التسعير إلى هذا المشروع.

ملفا `Architecture.txt` و`Enterprise Repository Structure.txt` في الجذر يصفان مرجعًا آخر محفوظًا دون تعديل؛ عند التعارض يُرجع إلى حزمة NexusServiceCloud الحالية و[سجل المصادر](docs/14-appendices/01-sources-glossary.md).

## ◈ حدود التسليم

- ملفات Markdown فقط؛ مخططات Mermaid داخل الوثائق للتفسير.
- المقترحات غير معتمدة تجاريًا أو أمنيًا أو تشغيليًا حتى يُسجل اعتمادها.
- لا يوجد ادعاء باكتمال API، أو تطبيق ITIL، أو جاهزية إنتاج، أو نجاح اختبارات تشغيل.
- هيكل منصة مستقبلي مذكور في التصميم لا يعني إنشاء مستودع تطبيق.
- الإصدارات، الأسعار، تكاليف الذكاء الاصطناعي، والتجربة المجانية تحتاج قرار مالك المنتج.
