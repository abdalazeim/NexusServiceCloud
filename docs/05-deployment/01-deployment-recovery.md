# تصميم النشر والترحيل والتعافي

NSC-DEP-01 | مقترح، دون ملفات تشغيل أو أوامر نشر | 2026-11-09.

## أنماط النشر

سحابي متعدد المؤسسات، أو محلي بمؤسسة واحدة مع بقاء حدود الصلاحيات. واجهة واتصال API خلف حافة آمنة، شبكة بيانات غير عامة، عامل مهام، قاعدة بيانات، مخزن مرفقات ونسخ احتياطي. لا يفترض وجود توافر عالٍ لمجرد تشغيل حاويات. فصل البيئات يشمل قواعد البيانات والأسرار والهوية ووجهات البريد، فلا ترسل بيئة الاختبار رسائل إلى مستخدمين حقيقيين.

## الترقية المقترحة

تغيير توسعي متوافق أولًا، ثم ترحيل بيانات قابل للاستئناف، ثم تبديل القراءة، ثم إزالة القديم في إصدار لاحق بعد التحقق. يحدد لكل تغيير أثر العامل والرسائل القديمة. اختبار ترقية نسخة قديمة، وتوافق القراءة، وخطة رجوع قبل أي إطلاق.

التراجع عن التطبيق لا يعني استعادة قاعدة البيانات تلقائيًا. عند تحول بيانات غير عكوس يختار الفريق إصلاحًا أماميًا أو استعادة مدروسة مع تسوية عمليات حدثت لاحقًا. لا تعد الهجرات قابلة للعكس دائمًا، ولا تجمع سياسة forward-only ووعد rollback شامل.

## ترحيل البيانات الأولية

تسلسل: المؤسسات والعضويات → المواقع والمجموعات → التصنيف والخدمات → القوالب والتقاويم وSLA → الطلبات التاريخية → المرفقات والروابط. تحفظ خريطة معرف المصدر ومعرف الوجهة ودفعة الاستيراد. لا تبدأ مؤقتات أو إشعارات لطلبات تاريخية دون قرار ترحيل صريح. تدقق عينات وعدد السجلات والعلاقات قبل قبول الدفعة.

## النسخ والاستعادة

يشمل النطاق قاعدة البيانات والمرفقات والإعدادات المعتمدة ومفاتيح فك التشفير بطريقة آمنة. هدف RPO 15 دقيقة وRTO 4 ساعات مقترح ويحتاج تقنية نسخ مستمر وتجربة لتثبيته؛ النسخ اليومي وحده لا يحقق RPO المذكور.

التمرين: اختيار نقطة استعادة → بيئة معزولة → استعادة البيانات والمرفقات → تحقق البصمات والروابط → تحقق العزل → تسوية Outbox والرسائل الخارجية → قياس الفقد والمدة → تقرير واعتماد. يمنع تكرار إخطار أو شراء خارجي بعد الاستعادة بمفاتيح عمليات محفوظة ومقارنة مع سجلات الوجهة عند الحاجة.

## شروط الانتقال للإنتاج مستقبلًا

عقد نطاق معتمد، حماية أسرار، نتائج عزل وقبول، تجربة استعادة، مراقبة فعالة، مسؤول مناوب، خطة رجوع وحدود فقد معروفة. لم تنفذ هذه الخطوات ولم ينشأ أي نشر في هذا التكليف.
