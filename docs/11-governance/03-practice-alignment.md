# مواءمة الممارسات ومنهج إدارة العمل

NSC-PRACTICE-01 | مواءمة مع محتوى القالب المحلي فقط | 2026-11-09.

القالب الأصلي يسرد 34 ممارسة تحت ITIL 4. هذه الوثيقة توضح أين يخدمها التصور، ولا تتحقق من إصدار المعيار الحالي أو تمنح شهادة التزام. ما يلي تجميع تحليلي للمحتوى المقدم، وليس نقلًا حرفيًا من مرجع رسمي خارجي.

## دعم مباشر في المنتج المقترح

مكتب الخدمة وإدارة الحوادث وطلبات الخدمة والكتالوج ومستوى الخدمة: FR-03/04/08. إدارة المشكلات وتمكين التغيير: FR-10/11. المعرفة: FR-16. الأصول وتكوين الخدمات: FR-13. الإصدارات والنشر: FR-12 مع حفظ نتيجة كل محاولة نشر. المشاريع: FR-12؛ القياس والتقارير: FR-18؛ الموردون: FR-14 بحدود العقود، دون ادعاء نظام متكامل لتقييم الموردين.

## دعم جزئي أو عبر عمليات المؤسسة

التحسين المستمر يستخدم التقارير وسجل إجراءات المراجعة. أمن المعلومات تدعمه الصلاحيات والتدقيق، لكنه يحتاج سياسة ومسؤولية خارج المنتج. المراقبة والأحداث تعتمد موصلات معتمدة لاحقًا. التوافر والسعة والأداء واستمرارية الخدمة تدعمها مقاييس وخطة تشغيل وتعافٍ. التحقق والاختبار يحكمهما ملف قبول؛ لا يعني وجود شاشة اختبار داخل المنتج.

تحليل الأعمال والبنية المعمارية والمخاطر وتصميم الخدمة تدعمها هذه الوثائق وقراراتها. تطوير البرمجيات وإدارة البنية التحتية ممارسات فريق التنفيذ مستقبلًا، وليستا وحدتين مطلوبتين تلقائيًا في واجهة المستخدم.

## خارج النطاق الوظيفي التفصيلي

المحفظة والاستراتيجية والعلاقات والتغيير التنظيمي والقوى العاملة والمواهب والإدارة المالية للخدمات تحتاج تحليلًا مستقلًا إذا أريد تحويلها إلى وحدات. وجود مشروع أو عقد أو سجل تكلفة لا يغطي تلقائيًا هذه الممارسات. لا يساوي عدد الممارسات عدد تطبيقات الخلفية أو الجداول.

## Agile وScrum وKanban

تستخدم مراحل تسليم صغيرة ومراجعات قبول للحصول على تغذية راجعة. داخل وحدة المشروع: task وstatus وassignee وcomments وtags وmilestone خط أساس P3، أما backlog وiteration وstory وacceptance criteria وWIP limits ومقاييس التدفق فامتداد P4.

قبل اعتماد Velocity يحدد الفريق وحدة التقدير وكيفية تثبيت نطاق الدورة ومعالجة النقل بين الدورات. قبل Burndown يحدد ما إذا كان يقيس جهدًا أم عدد عناصر، وكيف يظهر تغيير النطاق. لا تستخدم سرعة فريق للمقارنة العقابية مع فريق آخر، ولا تحول ساعات SLA إلى Story Points.

Odoo وGitHub Projects وJira أمثلة مقارنة واردة بالقالب المحلي؛ لم تُراجع ميزاتها أو أسعارها الحالية ولم يُعتمد أي منها كأداة لهذا المشروع. يقتبس التصميم الفكرة المشتركة للمهام والحالات والاعتماديات دون ادعاء مطابقة منتج بعينه.
