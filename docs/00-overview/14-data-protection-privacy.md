## 1. ملخص تنفيذي

تحدد هذه الوثيقة سياسات حماية البيانات والخصوصية لمنصة NexusServiceCloud. تركز على الامتثال لـ GDPR ومبادئ تقليل البيانات، الحقوق الفردية، فترات الاحتفاظ، والتصرفات الأمنية للبيانات الشخصية. التوثيق تصفري ولم تُنفذ ضوابط الخصوصية بعد.

---

## 2. نطاق البيانات الشخصية

| الفئة | الأمثلة | النطاق |
|--------|---------|-------|
| **المستفيدون** | الاسم، البريد، رقم الموظف، القسم، الطلبات، التعليقات | بيانات مستخدم المنصة |
| **الفنيون** | الاسم، البريد، المجموعة، المهارات، سجلات العمل، التقييمات | بيانات موظفين |
| **الموافقون** | الاسم، البريد، قرارات الموافقة، التواريخ | بيانات موظفين |
| **الموردون** | اسم الشركة، جهة الاتصال، العقود، أوامر الشراء | بيانات طرف ثالث |
| **مديرو المؤسسات** | الإعدادات، العضويات، السجلات الإدارية | بيانات إدارية |

---

## 3. مبادئ حماية البيانات

| المبدأ | التطبيق في NexusServiceCloud |
|--------|------------------------------|
| **القانونية والإنصاف والشفافية** | معالجة البيانات بناءً على موافقة أو عقد أو التزام قانوني؛ إشعار الخصوصية متاح |
| **تحديد الغرض** | تُستخدم البيانات فقط لأغراض إدارة الخدمات والدعم الفني |
| **تقليل البيانات** | جمع البيانات الضرورية فقط؛ لا توجد بيانات حساسة دون حاجة |
| **الدقة** | تمكين المستخدمين من تحديث بياناتهم؛ تصحيح غير دقيق عند الإشعار |
| **تقليل فترة التخزين** | حذف أو مجهولة البيانات بعد فترة الاحتفاظ المعتمدة |
| **الأمان والنزاهة** | تشفير أثناء النقل والتخزين، التحكم في الوصول، تدقيق الوصول |
| **المسؤولية** | توثيق عمليات المعالجة والاحتفاظ بسجلات التحقيق |

## 4. حقوق الأفراد (GDPR)

| الحق | الوصف | الآلية المقترحة |
|------|--------|----------------|
| **الحق في الإبلاغ** | إبلاغ المستخدم بما تُجمع من بيانات ولماذا | إشعار خصوصية في التسجيل وفي كل شاشة جمع بيانات |
| **الحق في الوصول** | طلب نسخة من البيانات الشخصية | واجهة تصدير بيانات المستخدم (PDF/JSON) |
| **الحق في التصحيح** | تصحيح بيانات غير دقيقة | نموذج تحديث الملف الشخصي |
| **الحق في الحذف (النسيان)** | طلب حذف البيانات الشخصية | عملية حذف مع استثناءات قانونية (سجلات التدقيق، الفواتير) |
| **الحق في التقييد** | تقييد المعالجة مؤقتًا | علامة تقييد في سجل المستخدم |
| **الحق في الاعتراض** | الاعتراض على المعالجة لحسтов مبررة | مراجعة يدوية من مسؤول الخصوصية |
| **حق نقل البيانات** | استلام البيانات بصيغة قابلة للنقل | تصدير آلي بصيغة JSON شائعة |
| **عدم الخضوع لقرارات آلية** | لا قرارات قانونية من الذكاء الاصطناعي دون تدخل بشري | مخرجات AI خاضعة للمراجعة البشرية (DOC-01، ADR-017) |

## 5. فترات الاحتفاظ (الاقتراح)

| النوع | المدة المقترحة | الملاحظات |
|------|--------------|-----------|
| الطلبات والحوادث | 3–7 سنوات | حسب متطلبات المؤسسة والامتثال |
| سجلات التدقيق | 3–7 سنوات | لا تُعدل أو تُحذف قبل المدة |
| المرفقات | مرتبطة بطلبها الأصلي | تُحذف مع الطلب أو تُأرشف |
| الإشعارات | 90 يومًا | قابلة للتكوين لكل مؤسسة |
| نسخ احتياطية | 30–90 يومًا | دورية مع تدوير |
| سجلات الدخول | 90 يومًا | مراقبة الوصول غير المصرح |

> **ملاحظة:** مدد الاحتفاظ غير محسومة؛ تُعتمد حسب كل مؤسسة ومتطلباتها القانونية.

## 6. التصرفات الأمنية للبيانات

| التصرف | التنفيذ المقترح |
|---------|-----------------|
| **التشفير أثناء النقل** | TLS 1.2+ لكل الاتصالات API و웹 |
| **التشفير أثناء التخزين** | تشفير قرص قاعدة البيانات ونسخ الاحتياطية |
| **إدارة المفاتيح** | مخزن أسرار مع تدوير دوري؛ لا تُخزن المفاتيح في الكود |
| **التحكم في الوصول** | RBAC/ABAC مع عزل tenant_id وRLS |
| **تسجيل الوصول** | سجل من وصل إلى أي بيانات ومتى ولماذا |
| **تحديد الهوية المجهولة** | مجهولة البيانات للتقارير الإحصائية عند الإمكان |
| **الحد الأدنى من الصلاحيات** | كل مكون يحصل على أقل الصلاحيات اللازمة لعمله |

## 7. انتهاكات البيانات (Breach Response)

| الخطوة | الإجراء | المسؤول |
|------|---------|--------|
| **الكشف** | مراقبة غير طبيعية، تنبيه أمني، إشعار خارجي | فريق العمليات |
| **التحقيق** | تحديد نطاق الاختراق، البيانات المتأثرة، السبب | مهندس الأمان |
| **الاحتواء** | عزل الأنظمة المتأثرة، إلغاء رموز الوصول | فريق العمليات |
| **الإشعار** | إشعار الجهات التنظيمية والمتأثرين خلال المهلة القانونية | قانوني/امتثال |
| **التعافي** استعادة الخدمات، إصلاح الثغرة، مراجعة ما بعد الحادث | فريق الهندسة |

> يتطلب إشعار انتهاكات GDPR خلال 72 ساعة من اكتشاف الانتهاك حيثما ينطبق.
