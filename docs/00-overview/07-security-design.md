## 1. ملخص تنفيذي

تحدد هذه الوثيقة نموذج الصلاحيات والعزل والتهديدات وتصميم معالجتها لمنصة NexusServiceCloud. تعتمد المنصة على **تفويض تطبيقي مركب** (هوية فعالة + عضوية مؤسسة + فعل مسموح + نطاق مكتب/مجموعة + قيد كائن وحالته) مع **عزل مستأجر** عبر `tenant_id` وـ RLS دفاع إضافي في PostgreSQL. لا تُعتبر الوثيقة نتيجة فحص أمنية أو شهادة امتثال.

## 2. نموذج التفويض (Authorization Model)

### 2.1 قرار التفويض

```
القرار = هوية فعالة + عضوية مؤسسة + فعل مسموح + نطاق مكتب/مجموعة + قيد كائن وحالته
```

الواجهة تخفي الأفعال غير المتاحة لتحسين الاستخدام، لكن الخادم يعيد التحقق في كل طلب. صلاحية القائمة لا تعني صلاحية المرفق أو التقرير المشتق.

### 2.2 الأدوار والصلاحيات

| الدور | الأفعال المسموحة | القيود |
|------|----------------|--------|
| **المستفيد** | إنشاء طلب، قراءة طلباته، إضافة رد عام، مشاركة طلب (تفويض صريح) | لا يرى طلبات الغير، لا يعالج |
| **الفني** | قراءة ومعالجة نطاق مجموعاته، ملاحظات داخلية مسموحة، تسجيل عمل | لا يغير سياسة SLA، لا يمنح أدوار |
| **قائد الدعم** | إعادة تعيين، تصعيد، تقارير فريقه | لا يعتمد شراء لمجرد كونه قائدًا |
| **الموافق** | قراءة مورد مراجعته، إضافة قرار ضمن نسخة صحيحة | لا يحرر طلب الموافقة |
| **مدير الأصل/المخزن** | حركات، حجز، استلام ضمن اختصاصه | ربط أصل بتذكرة لا يمنح نصها تلقائيًا |
| **مدير المؤسسة** | إدارة إعدادات مؤسسته وأدوارها | مكاتب سرية تحتاج منحًا مستقلًا مدققًا |
| **المدقق** | قراءة أدلة، تصدير محدود ومراقب | لا تعديل، لا إلغاء |
| **مسؤول المنصة** | إدارة الحالة التشغيلية | وصول استثنائي يحتاج سببًا واعتمادًا وحدًا زمنيًا وسجلًا |

### 2.3 العزل tenant-level

- الهوية تأتي من عضوية مصادق عليها؛ لا يُعتمد رأس HTTP أو حقل حمولة دون التحقق.
- دور التشغيل ليس مالك قاعدة البيانات ولا يملك تجاوز RLS.
- يضبط السياق لكل معاملة ويزال عند انتهائها؛ فشل السياق يعني المنع.
- نفس السياسة تشمل العامل والتصدير والبحث والتخزين المؤقت والمرفقات والاشتراكات اللحظية.
- مفاتيح cache تحمل المؤسسة ونطاق الصلاحية؛ إلغاء الوصول يبطل النتائج الحساسة.
- روابط الملفات قصيرة الصلاحية تصدر بعد تفويض؛ أسماء الملفات ليست حماية.
- عزل المؤسسات لا يكفي لموارد HR داخل المؤسسة؛ `service_desk_id` ونطاق جمهور السجل جزء من التفويض.
- التقارير الإجمالية لا تكشف أعدادًا حساسة لنطاق غير مرئي.

## 3. التهديدات وتصميم معالجتها

| التهديد | التصميم المقترح | مرجع الاختبار |
|---------|----------------|--------------|
| تبديل معرف كائن (IDOR) | تفويض على المورد والروابط والمرفقات | AC-01، AC-06، AC-22 |
| تزوير موافقة | هوية موثقة، تحقق النسخة، منع إعادة الاستخدام | AC-09 |
| حقن محتوى في تعليق/مرفق | تطبيع إدخال، عرض آمن، فحص ملفات، عزل قبل النشر | — |
| SSRF عبر Webhook | وجهات مسموحة، تحقق عنوان الوجهة الفعلي، فصل شبكة الموصلات | — |
| أسرار موصل مسربة | مخزن أسرار، عدم إظهار القيمة بعد الحفظ، تدوير، قيود خروج | — |
| حقن تعليمات AI عبر البحث | نصوص غير موثوقة، وصول بحسب المصدر، مراجعة بشرية | AC-20 |
| تصدير ضخم / استعلام مرهق | حدود استخدام، صلاحية تصدير، رابط محدود، تدقيق العملية | — |

## 4. الاحتفاظ والتدقيق

- تسجيل الحدث لا يثبت وحده عدم قابليته للتلاعب.
- يمنع حساب التطبيق تعديل سجلات التدقيق؛ تقترح نسخة مستقلة ذات صلاحية كتابة محدودة.
- إثبات المقاومة للتغيير يحتاج تحققًا منفصلًا.
- مدد الاحتفاظ للطلبات والمرفقات والتدقيق والنسخ الاحتياطية غير محسومة؛ تُعتمد حسب المؤسسة.

### 4.1 تصنيف البيانات

| التصنيف | الأمثلة | الوصف |
|---------|---------|-------|
| **عام** | المقالات المنشورة للعامة فقط | يمكن النشر علنًا |
| **داخلي** | الإجراءات والسياسات | موظفو المؤسسة |
| **مقيد** | بيانات الموظفين والعقود | نطاق الوصول المصرح |
| **سري** | الاعتمادات، مفاتيح الوصول | 최소 حد من الصلاحيات |

> كلمات المرور ومفاتيح الوصول لا تدخل طلبًا أو تقريرًا أو prompt.
